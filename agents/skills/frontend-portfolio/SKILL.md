# Portfolio Polish

When working on this portfolio:

1. Read `/PORTFOLIO_SPEC.md` before making design or content decisions.

2. Treat PORTFOLIO_SPEC.md as the source of truth for:
   - design direction
   - factual content
   - project information
   - experience
   - responsive requirements
   - accessibility
   - frontend architecture

3. Do not rebuild the application from scratch.

4. Improve the existing implementation incrementally.

5. Never invent:
   - technologies
   - project features
   - experience
   - metrics
   - dates
   - GitHub links
   - LinkedIn links

6. Prioritize work in this order:
   - factual correctness
   - functional correctness
   - global design system
   - homepage hierarchy
   - project presentation
   - responsive design
   - accessibility
   - performance
   - final production QA

7. The desired visual direction is:
   - dark-first
   - near-black neutral background
   - off-white typography
   - restrained emerald accent
   - clean professional typography
   - subtle Bento composition
   - large engineering case studies
   - restrained technical diagrams
   - subtle professional motion

8. Avoid:
   - generic AI landing-page patterns
   - purple glow styling
   - excessive gradients
   - excessive glassmorphism
   - excessive rounded cards
   - hacker aesthetics
   - unnecessary animations
   - fake terminal UI
   - skill percentages

9. Before modifying a section:
   - inspect the existing implementation
   - compare it against PORTFOLIO_SPEC.md
   - preserve useful existing architecture

10. After changes:
   - run TypeScript checks
   - run lint
   - run production build where appropriate
   - report remaining issues
